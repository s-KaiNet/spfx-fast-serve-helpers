# Styles, localization and assets in SPFx

## Summary

SPFx injects component styles from JavaScript, scopes CSS module class names with a hash suffix, and resolves theme tokens against the page's theme at runtime. Localized strings are separate per-locale modules addressed by a name such as `HelloWorldWebPartStrings`. Static assets are imported as URLs with typings generated by the build. `fast-serve` keeps each of these conventions so source written for `heft build` works unchanged.

## Current Knowledge

### CSS modules and class-name hashing

- In SPFx 1.24 only `*.module.scss` / `*.module.css` files are CSS modules; other style files are global.
- heft compiles Sass to CSS first, then `@microsoft/sp-css-loader` turns `.module.*.css` into a module that calls `loadStyles(css, true)` and default-exports a class map (`{ helloWorld: "helloWorld_587db475" }`). Class names get a suffix of `_` plus 8 characters of a hash.
- `fast-serve` names classes in the same `<local>_<8-char hash>` shape with camelCase keys, so `styles.helloWorld` works; the exact hash differs from heft, so never hard-code generated names.
- Some libraries (for example PnP controls) import `.module.scss` but publish only the compiled `.module.scss.css`; `fast-serve` compiles those with `@microsoft/sp-css-loader` like heft.
- Sass `~` imports (`@import '~@fluentui/...'`) resolve to packages.
- Typings for `.module.scss` live in `temp/sass-ts/**/*.d.ts`; `fast-serve` regenerates them byte-identically to `heft build`, so new classes are typed without a build.

### Theme tokens

- Styles may contain tokens like `"[theme:themePrimary, default: #0078d4]"`. At runtime `@microsoft/load-themed-styles` `loadStyles` replaces them with the current page theme (`window.__themeState__.theme`), falling back to the default.
- `fast-serve` resolves tokens once per style insert or hot update, while Vite still owns the `<style>` tags so CSS HMR works. It does not watch theme changes: switching the site theme on an open page needs a reload.

### Localized resources

- `config/config.json` `localizedResources` maps a module name to a path pattern, e.g. `"HelloWorldWebPartStrings": "lib/webparts/helloWorld/loc/{locale}.js"`. Code imports the name (`import * as strings from 'HelloWorldWebPartStrings'`), backed by a `.d.ts` declaration.
- heft makes the name an external and emits `<Name>_<locale>.js` files referenced as `path` or `localizedPath` script resources; SharePoint picks one by UI culture.
- A loc file must be an AMD module `define([], function () { return { ... }; });`. heft copies the compiled file as is, so `export default` builds but breaks under RequireJS, and `export =` fails to compile. `fast-serve` accepts JavaScript or TypeScript loc files and warns about non-AMD ones.
- `fast-serve` serves strings for the `locale` option (default `en-us`, falling back to `en-us` per resource).

### Static assets

- `import logo from './assets/logo.png'` (or a relative `require`) yields a URL. heft emits hashed files under `dist/`, located relative to the bundle's own script URL at runtime; `fast-serve` gives absolute dev-server URLs such as `https://localhost:4321/src/webparts/hello/assets/logo.png`.
- Typings come from Heft's static-asset-typings step (`temp/static-asset-ts/**/*.d.ts`, for the extensions configured by the rig: `.gif`, `.jpg`, `.jpeg`, `.png`, `.svg`, `.webp`), found through the rig tsconfig's `rootDirs`. Other extensions need a hand-written `declare module`.
- Manifest icons with a relative `./` path (`iconImageUrl` in `preconfiguredEntries` or command set `items`) are served from `src` in dev; a bare relative path (`icons/x.png`) is passed through, as in heft.
